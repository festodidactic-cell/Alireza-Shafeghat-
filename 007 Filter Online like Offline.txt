ببین اولا قرار نیست هرچه فیلتر نشان داد من ترید کنم. شرط عقل اینست که پس از خروجی فیلتر خودم هم تحلیل کنمو زیر ذره بین ببرم. البته این بیشتر برای فیلتر آفلاین کاربرد دارد. در آینده که قصد طراحی فیلتر آنلاین دارم آنجا حساسیت بیشتر است.برای قسمت بعدی میخواهم سه فیلتر فوق که منتشر کردی در نظر بگیری جمیع حالتهای مختلف و معایب و مزایای آن را. در نظر بگیری و یک فیلتر بسازی به صورت آنلاین عمل کند البته در زمینه فیلتر ان لاین برای نوسان بعدا صحبت میکنیم. ولی در حال حاضر به عنوان فیلتر چهارم میخواهم یک فیلتر آنلاین طراحی کنی که پایه آن سه فیلتر فوق باشد. یعنی من قرار است این فیلتر را در زمان معاملات استفاده کنم با خصوصیات فیلتر های بالا که کار کردی. فیلتری باشد که سهمی بدون ریسک را پیدا کند با تمام شرایط بالا ولی معاملات جاری هم در نظر بگیرد و از قوت لحظات خاص آن استفاده کند. میدانی چرا؟؟ چون ممکن است تو فیلتر آنلاینت سهمی را تشخیص دهد که در روز بعدی معاملات ناگهان از دست برود و اجازه ورود ندهد. ولی اگر در روز معاملات باشد شاید قبل از شروع حرکت سهم توانستیم انرا شکار کنیم. هدف هم اینست سهمی معرفی شود که رشدش برای آینده ادامه دار باشد مثل بالا فقط از نقاط قوت معاملات لحظه ای هم استفاده کند که پاسخ تثبیت شده تری بدهد. اینجا باید ریسک اشتباه کمتر باشد چون ممکن است پس از خروجی فیلتر من فرصت زیادی برای آنالیز عمیق پیدا نکنم و سهم از دست برود یا عجولانه انتخاب شود. همچنین فیلتر حالت بهینه و بسیار هوشمند عمل کند مانند یک تریدر بسیار زیرک و فرصت طلب با یک علم بسیار گسترده که تمام زیر و بم سهام را در نظر دارد
-----------

کاملاً درست است. **فیلتر نباید جای تحلیل تو را بگیرد.** مخصوصاً فیلترهای آفلاین باید یک Universe باکیفیت بسازند و تو بعداً سهم را زیر ذره‌بین ببری.

اما درباره فیلتر آنلاین یک تفاوت مهم داریم: چون زمان تصمیم‌گیری کوتاه‌تر است، باید **حساسیت به خطای مثبت کاذب را بیشتر کنیم**. من هم «سهم بدون ریسک» را به‌عنوان هدف فنی قبول نمی‌کنم؛ چنین چیزی وجود ندارد. هدف این فیلتر باید این باشد:

> **سهمی را پیدا کند که ساختار میان‌مدت خوبی دارد و همین حالا معاملات جاری نیز آن ساختار را تأیید می‌کنند، بدون اینکه سهم وارد مرحله‌ای شده باشد که بخش عمده حرکت را از دست داده‌ایم.**

این می‌شود فیلتر شماره ۴.

# فیلتر شماره ۴ — **Live Smart Entry Confirmation**

### فیلتر آنلاین تأیید هوشمند ورود

این فیلتر از سه لایه قبلی استفاده می‌کند:

**فیلتر ۱:** حذف سهم‌های مشکل‌دار از نظر نقدشوندگی و گیرکردن
**فیلتر ۲:** تشخیص ساختار جمع‌آوری
**فیلتر ۳:** تشخیص Pre-Breakout
**فیلتر ۴:** بررسی می‌کند که آیا **همین الآن بازار دارد آن سناریو را تأیید می‌کند یا خیر.**

نکته مهم: این فیلتر قرار نیست صرفاً «صف خرید» را پیدا کند. اتفاقاً صف خرید سنگین را یک نقطه منفی می‌داند، چون ممکن است بهترین فرصت ورود گذشته باشد.

true==function()
{

    // FILTER 04

    // هدف:
    // پیدا کردن سهمی که:

    // 1) از نظر ساختار تاریخی سالم باشد
    // 2) نقدشوندگی مناسبی داشته باشد
    // 3) نشانه های Accumulation در سابقه آن دیده شود
    // 4) در محدوده Pre-Breakout قرار گرفته باشد
    // 5) اکنون معاملات جاری آن سناریو را تایید کنند
    // 6) قدرت خریدار حقیقی فعلی بالا باشد
    // 7) خالص خرید حقیقی فعلی مثبت باشد
    // 8) حجم جاری نسبت به سابقه مناسب باشد
    // 9) قیمت فعلی به مقاومت نزدیک باشد
    // 10) اما هنوز در صف خرید قفل نشده باشد
    // 11) سهم بیش از حد از نقطه ورود مناسب فاصله نگرفته باشد
    //

    //
    // مهم:
    // خروجی = "کاندید بررسی فوری"
    // خروجی ≠ دستور خرید
    //
    // ============================================================


    // ============================================================
    // 1) MINIMUM HISTORICAL DATA
    // ============================================================

    if(typeof [ih][29]=="undefined")
        return false;


    // ============================================================
    // 2) HISTORICAL VALID DAYS
    // ============================================================

    var ValidDays=function(n)
    {
        var c=0;

        for(var i=0;i<n;i++)
        {
            if(typeof [ih][i]!="undefined" &&
               [ih][i].PriceMin>0 &&
               [ih][i].PriceMax>0 &&
               [ih][i].PClosing>0 &&
               [ih][i].QTotTran5J>0)
            {
                c++;
            }
        }

        return c;
    };


    if(ValidDays(30)<25)
        return false;


    // ============================================================
    // 3) HISTORICAL MIN / MAX
    // ============================================================

    var MinPrice=function(n)
    {
        var min=999999999999;

        for(var i=0;i<n;i++)
        {
            if(typeof [ih][i]!="undefined" &&
               [ih][i].PriceMin>0 &&
               [ih][i].PriceMin<min)
            {
                min=[ih][i].PriceMin;
            }
        }

        return min;
    };


    var MaxPrice=function(n)
    {
        var max=0;

        for(var i=0;i<n;i++)
        {
            if(typeof [ih][i]!="undefined" &&
               [ih][i].PriceMax>max)
            {
                max=[ih][i].PriceMax;
            }
        }

        return max;
    };


    // ============================================================
    // 4) HISTORICAL AVERAGE VOLUME
    // ============================================================

    var AvgVolume=function(n)
    {
        var sum=0;
        var c=0;

        for(var i=0;i<n;i++)
        {
            if(typeof [ih][i]!="undefined" &&
               [ih][i].QTotTran5J>0)
            {
                sum += [ih][i].QTotTran5J;
                c++;
            }
        }

        if(c==0)
            return 0;

        return sum/c;
    };


    // ============================================================
    // 5) HISTORICAL AVERAGE TRANSACTION COUNT
    // ============================================================

    var AvgTrades=function(n)
    {
        var sum=0;
        var c=0;

        for(var i=0;i<n;i++)
        {
            if(typeof [ih][i]!="undefined" &&
               [ih][i].ZTotTran>0)
            {
                sum += [ih][i].ZTotTran;
                c++;
            }
        }

        if(c==0)
            return 0;

        return sum/c;
    };

    // 6) AVERAGE DAILY RANGE
    // ============================================================

    var AvgRange=function(n)
    {
        var sum=0;
        var c=0;

        for(var i=0;i<n;i++)
        {
            if(typeof [ih][i]!="undefined" &&
               [ih][i].PriceYesterday>0)
            {
                sum +=
                ([ih][i].PriceMax-[ih][i].PriceMin)
                /[ih][i].PriceYesterday;

                c++;
            }
        }

        if(c==0)
            return 0;

        return sum/c;

    // ============================================================

    var SupportTouches=function()

        var min60=MinPrice(60);

        if(min60<=0)

        var c=0;

        for(var i=2;i<58;i++)

            if(typeof [ih][i]!="undefined" &&
               typeof [ih][i-1]!="undefined" &&
               typeof [ih][i+1]!="undefined")

                }

    else if(supportTouches>=2)

    // COMPRESSION
    // ------------------------------------------------------------

    if(compression>=8)

    else if(compression>=6)
        score+=10;
    else if(compression>=4)
        score+=7;
    else
        score+=4;

    // ------------------------------------------------------------

    if(volumeStructure==2)
        score+=8;
    else if(volumeStructure==1)
        score+=4;


    // ------------------------------------------------------------
    // CURRENT BUYER POWER
    // ------------------------------------------------------------

    if(buyerPower>=2.50)
        score+=15;

    else if(buyerPower>=2.00)
        score+=13;

    else if(buyerPower>=1.70)
        score+=11;

    else if(buyerPower>=1.50)
        score+=8;

    else if(buyerPower>=1.30)
        score+=5;

    // ------------------------------------------------------------

    else if(realNet>=(ct).Buy_I_Volume*0.15)

    else if(realNet>0)
        score+=4;


    // ------------------------------------------------------------
    // CURRENT VOLUME
    // ------------------------------------------------------------

    if(tvol>=av30*1.50)
        score+=12;

    else if(tvol>=av30*1.00)
        score+=10;

    else if(tvol>=av30*0.70)
        score+=7;

    else if(tvol>=av30*0.40)
        score+=4;

    else
        score+=2;


    // ------------------------------------------------------------
    // TRANSACTION ACTIVITY
    // ------------------------------------------------------------

    if(avgTrades30>0)
    {
        if(tno>=avgTrades30*1.50)
            score+=8;

        else if(tno>=avgTrades30)
            score+=6;

        else if(tno>=avgTrades30*0.70)
            score+=3;
    }


    // ------------------------------------------------------------
    // DISTANCE TO RESISTANCE
    // ------------------------------------------------------------

    if(dist60>=1.5 && dist60<=4)
        score+=12;

    else if(dist60<=6)
        score+=10;

    else if(dist60<=8)
        score+=6;


    // ------------------------------------------------------------
    // INTRADAY PRICE POSITION
    // ------------------------------------------------------------

    if(tmax>tmin && tmax>0 && tmin>0)
    {
        var ip=
        ((pl-tmin)/(tmax-tmin))*100;

        if(ip>=80)
            score+=8;

        else if(ip>=70)
            score+=6;

        else if(ip>=60)
            score+=4;
    }


    // ============================================================
    // NEGATIVE PENALTIES
    // ============================================================

    // ------------------------------------------------------------
    // Too close to resistance without volume
    // ------------------------------------------------------------

    if(dist60<1.5 && tvol<av30)
        score-=8;


    // ------------------------------------------------------------
    // Buyer power weak
    // ------------------------------------------------------------

    if(buyerPower<1.50)
        score-=6;


    // ------------------------------------------------------------
    // Price too close to upper limit
    // ------------------------------------------------------------

    if(tmax>0 && pc>=tmax*0.985)
        score-=8;


    // ------------------------------------------------------------
    // Excessive chase
    // ------------------------------------------------------------

    if(dist60<0.8)
        score-=10;


    // ------------------------------------------------------------
    // Weak current transaction
    // ------------------------------------------------------------

    if(tno<avgTrades30*0.50)
        score-=5;


    // ============================================================
    // FINAL QUALITY GATE
    // ============================================================

    if(score>=90)
        return true;

    return false;

* کف کجا بوده؟

* آیا دامنه نوسان فشرده شده؟
* آیا حجم روزهای مثبت نسبت به منفی کیفیت بهتری دارد؟
* آیا سهم نقدشونده است؟
* آیا سابقه گیرکردن شدید دارد؟

اما امتیاز خیلی بالاتر را برای:

```text
1.70
2.00
2.50+
```

می‌دهد.

---

# چرا 2.5 خیلی مهم‌تر از 1.3 است؟

فرض کن:

### سهم A

```text
Buyer Power = 1.31
```

### سهم B

```text
Buyer Power = 2.35
```

هر دو شرط پایه را پاس می‌کنند، ولی قطعاً نمی‌خواهم آنها را از نظر کیفیت جاری یکسان ببینم.

به همین دلیل **شرط سخت + Score** را با هم ترکیب کرده‌ام.

---

# خالص خرید حقیقی

فقط قدرت خریدار کافی نیست.

ممکن است:

```text
سرانه خرید بالا
+
سرانه فروش هم بالا
```

باشد.

پس:

```text
Buy_I_Volume - Sell_I_Volume
```

هم باید مثبت باشد.

این باعث می‌شود صرفاً نسبت سرانه‌ها ما را فریب ندهد.

---

# حجم جاری

اینجا یک نکته بسیار مهم وجود دارد.

در فیلتر آفلاین:

> حجم روزانه

را با میانگین‌های تاریخی مقایسه می‌کردیم.

اما در فیلتر آنلاین:

> **همین حجم فعلی**

اهمیت دارد.

بنابراین فیلتر می‌پرسد:

> آیا امروز همین الآن مشارکت معاملاتی قابل توجهی در حال شکل‌گیری است؟

نه اینکه فقط:

> «این سهم در گذشته خوب بوده.»

---

# تعداد معاملات جاری

این یکی از قسمت‌های مهم فیلتر است که خیلی‌ها نادیده می‌گیرند.

دو سهم را تصور کن:

### سهم اول

```text
حجم = زیاد
تعداد معاملات = کم
```

ممکن است چند معامله بزرگ علت حجم باشند.

### سهم دوم

```text
حجم = زیاد
تعداد معاملات = زیاد
```

نشانه مشارکت گسترده‌تری است.

بنابراین من `tno` را هم وارد Score کرده‌ام.

---

# قیمت باید در نیمه قوی دامنه امروز باشد

این قسمت:

```text
intradayPosition
```

بررسی می‌کند که قیمت فعلی نسبت به:

```text
کف امروز
تا
سقف امروز
```

کجاست.

مثلاً:

```text
کف = 100
سقف = 110
قیمت = 108
```

یعنی تقریباً در ۸۰٪ دامنه روزانه قرار دارد.

این با:

```text
قیمت = 101
```

رفتار یکسانی ندارد.

---

# اما چرا قیمت نزدیک سقف روزانه را کورکورانه خوب نگرفته‌ام؟

چون این یک دام است.

ممکن است:

```text
قیمت نزدیک سقف
+
Buyer Power بالا
```

ببینیم.

اما اگر سهم در آستانه صف خرید باشد، ممکن است:

> **فرصت ورود مناسب تمام شده باشد.**

بنابراین فیلتر این وضعیت را جریمه می‌کند.

---

# یک نکته بسیار مهم درباره هدف این فیلتر

تو گفتی:

> ممکن است فردا سهم را از دست بدهیم، اما امروز بتوانیم قبل از حرکت بگیریمش.

دقیقاً.

بنابراین فیلتر ۴ **نباید منتظر Breakout کامل بماند.**

اگر منتظر این باشیم:

```text
Resistance Break
+
Volume Explosion
+
Queue
```

آن‌وقت بخشی از مزیت فیلتر از بین می‌رود.

هدف این است:

```text
Accumulation
       ↓
Compression
       ↓
Pre-Breakout
       ↓
CURRENT BUYER CONFIRMATION
       ↓
Potential Move
```

نه:

```text
Breakout
       ↓
صف خرید
       ↓
حالا وارد شو!
```

---

# فیلتر ۴ چه سهمی را عمداً حذف می‌کند؟

## ۱. سهم بسیار کم‌معامله

حتی اگر تکنیکال زیبا باشد.

---

## ۲. سهمی که تاریخچه نقدشوندگی بدی دارد

چون هدف تو فقط سود نیست؛ **قابل خروج بودن** هم هست.

---

## ۳. سهمی که در مقاومت است ولی حجم تأیید نمی‌کند

این یکی بسیار مهم است.

```text
نزدیک مقاومت
+
حجم ضعیف
```

لزومی ندارد Breakout باشد.

---

## ۴. سهمی که قدرت خریدار فقط ظاهری است

اگر Buyer Power ضعیف باشد، حذف می‌شود.

---

## ۵. سهمی که تقریباً قفل صف خرید شده

چون دیگر Entry Quality کاهش پیدا کرده.

---

## ۶. سهمی که از مقاومت بیش از حد فاصله گرفته

این دیگر Pre-Breakout نیست؛ ممکن است بخشی از حرکت اتفاق افتاده باشد.

---

# ولی یک اصلاح بسیار مهم نسبت به درخواست تو

تو گفتی:

> «قوت لحظات خاص معاملات»

اینجا باید یک محدودیت فنی را کاملاً جدی بگیریم.

**این فیلتر آنلاین یک Snapshot از وضعیت جاری بازار را می‌بیند.**

یعنی اگر سیستم را در:

```text
09:45
```

اجرا کنی، یک وضعیت دارد.

اگر در:

```text
10:05
```

اجرا کنی، وضعیت دیگری دارد.

بنابراین نمی‌توانیم فقط با یک اجرای فیلتر بفهمیم:

> «Buyer Power در ۱۰ دقیقه گذشته پیوسته در حال افزایش بوده.»

مگر اینکه پلتفرم برای آن داده Intraday History در اختیار فیلتر قرار دهد.

پس این فیلتر **قدرت لحظه فعلی** را استفاده می‌کند، ولی ادعا نمی‌کند که تاریخچه ۵/۱۰/۱۵ دقیقه‌ای قدرت خریدار را دارد.

این تمایز برای طراحی حرفه‌ای بسیار مهم است.

---

# و این دقیقاً زمینه فیلتر شماره ۵ خواهد بود

به نظرم بعد از اینکه این فیلتر را روی بازار واقعی تست کردیم، فیلتر بعدی باید چیزی بسیار متفاوت باشد:

## **Live Momentum Transition Detector**

که دنبال این اتفاق باشد:

```text
T0:
Buyer Power متوسط

↓

T1:
Buyer Power افزایش

↓

T2:
حجم معاملات افزایش

↓

T3:
قیمت از محدوده قبلی عبور

↓

T4:
سرانه خرید بیشتر

↓

T5:
فروشنده‌ها جذب می‌شوند

↓

T6:
قیمت هنوز صف خرید نشده

↓

SIGNAL
```

یعنی به جای اینکه بپرسیم:

> «الان خریدار قوی هست؟»

بپرسیم:

> **«آیا قدرت خریدار دارد همین الآن از حالت عادی به حالت غیرعادی تغییر می‌کند؟»**

این از نظر من برای **نوسان‌گیری آنلاین** بسیار قدرتمندتر است، ولی همان‌طور که خودت گفتی فعلاً نباید با فیلتر ۴ قاطی شود.

# معماری نهایی سیستم تا اینجا

```text
                 ┌─────────────────────┐
                 │     FILTER 1        │
                 │ Liquidity / Risk    │
                 └──────────┬──────────┘
                            ↓
                 ┌─────────────────────┐
                 │     FILTER 2        │
                 │ Accumulation Score  │
                 └──────────┬──────────┘
                            ↓
                 ┌─────────────────────┐
                 │     FILTER 3        │
                 │ Pre-Breakout        │
                 └──────────┬──────────┘
                            ↓
                 ┌─────────────────────┐
                 │     FILTER 4        │
                 │ Live Smart Entry     │
                 │ Confirmation         │
                 └──────────┬──────────┘
                            ↓
                    تحلیل شخصی تو
                            ↓
                       تصمیم نهایی
```

و این ساختار را من ترجیح می‌دهم به یک «ابر‌فیلتر» که صد شرط را همزمان اعمال کند.

چون **فیلترهای آفلاین وظیفه کشف ساختار را دارند و فیلتر آنلاین وظیفه تأیید زنده آن ساختار را.**

یک نکته دیگر هم مهم است: در مستندات فایل، داده تاریخی `[ih]` و داده جاری `(ct)` و آمار تجمیعی `[is]` از هم تفکیک شده‌اند؛ بنابراین در طراحی‌های بعدی هم باید همین مرزبندی را حفظ کنیم و چیزی مثل «قدرت خرید ۳۰ روز گذشته» را از داده‌ای که صرفاً وضعیت جاری حقیقی/حقوقی را می‌دهد، جعل نکنیم.  

**نتیجه عملی:** فیلتر ۴ را من به‌عنوان «فیلتر سیگنال خرید» تعریف نمی‌کنم؛ آن را **فیلتر انتخاب فرصت زنده با کیفیت بالا** می‌دانم. این دقیقاً جای درستی برای تحلیل سریع تو قبل از تصمیم نهایی است.
